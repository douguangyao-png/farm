# 认养农业 SaaS · 技术选型与 MVP 排期

> ⚠️ **本文档的技术栈结论已被更新**：后端选型由「Go / Java」改为 **.NET 10 LTS**，论证见 `11-后端技术选型评估-NET可行性.md`；完整交付方案与排期以 `12-产品与技术交付方案-NET版.md` 为准。本文的 MVP 范围界定仍有参考价值。

## 1. 技术栈选型

| 层 | 选型 | 说明 |
|---|---|---|
| 前端（C 端） | uni-app / Taro | 一套代码出微信小程序 + H5 |
| 前端（后台） | Vue3 + Element Plus | 经营者 Web 后台、平台管理端 |
| 移动（管家） | uni-app 或企微小程序 | 农事打卡、客户跟进 |
| 后端 | Go（推荐）/ Java | 高并发选 Go；团队熟悉选 Java；前期 Node 单体可验证 |
| API 网关 | Kong / Nginx | 路由、限流、鉴权 |
| 业务库 | PostgreSQL | 强一致、JSON 支持（specs 字段） |
| 缓存 | Redis | 会话、热点、分布式锁 |
| 时序库 | TDengine / InfluxDB | 传感器高频数据 |
| 对象存储 | MinIO / OSS | 视频图片 |
| IoT | EMQX（MQTT） | 设备接入、消息桥接 |
| 直播 | SRS / WebRTC | 低延迟农场直播 |
| 支付 | 微信支付服务商模式 | 分账（平台+经营者） |
| 电子合同 | e签宝 / 法大大 | 合规合同签署 |
| 部署 | Docker + K8s | 前期云 Serverless 降本，验证后上 K8s |
| 可观测 | Prometheus + Grafana + ELK | 监控、日志、告警 |

## 2. MVP 范围（先跑通，不贪全）

**纳入 MVP：**
- 经营者后台：基地/资产台账、认养商品配置、订单管理、客户管理
- 消费者小程序：认养商城、我的认养、生长档案时间轴（照片/视频打卡）、支付
- 基础溯源（时间轴即溯源）、微信支付（含分账雏形）
- 管家移动端：农事一键打卡（核心，解决透明化）

**暂缓（二期）：**
- 深度 IoT（摄像头/传感器实时流）→ 先用"管家打卡+照片"替代
- 直播、区块链存证、农业保险对接、AI 图像识别
- 复杂营销（拼团/分销）先放优惠券

## 3. 12 周开发排期

| 阶段 | 周次 | 目标 |
|---|---|---|
| 需求与设计 | W1–2 | PRD 定稿、UI 原型、DB 设计、接口契约 |
| 基础平台 | W3–4 | 多租户框架、鉴权、后台骨架、DB 落地 |
| 经营者后台 | W4–7 | 基地/资产、商品、订单、客户模块 |
| 消费者小程序 | W6–9 | 商城、我的认养、生长档案、支付联调 |
| 管家端 + 溯源 | W8–10 | 农事打卡、时间轴溯源、支付分账打通 |
| 试点上线 | W11–12 | 1–2 个真实农场灰度、跑通 50–100 认养人闭环、修复 |

> 关键路径：多租户框架（W3）→ 商品/订单（W4–7）→ 支付分账（W9–10）→ 试点（W11–12）。

## 4. 团队配置建议（MVP 期）

| 角色 | 人数 | 职责 |
|---|---|---|
| 产品经理 | 1 | 需求、流程、合规规则 |

| 前端 | 2 | 小程序 + 后台 + 管家端 |
| 测试/运维 | 1 | 质量、部署、监控 |
| 农业顾问（兼职） | 1 | SOP、合规、基地对接 |

合计约 6–7 人，可在 12 周内完成 MVP 并落地试点。
