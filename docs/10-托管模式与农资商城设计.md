# 10 · 托管模式与农资商城设计（全托管 / 半托管 / 不托管）

> 本文档是 01-PRD 的增补模块。它解决一个问题：**同一块地，怎么卖给"只想收货的人"和"想自己下地的人"，并且让后者更便宜、但给农场赚回更多钱。**

---

## 一、为什么必须做这三档

| 现状痛点 | 三档托管带来的改变 |
|---|---|
| 认养费 1280 元起，把大量感兴趣的人挡在门外 | 不托管 **500 元起**，门槛降 61%，先用低价获客，再用农资与服务把钱赚回来 |
| 用户想要"参与感"，但现有产品只能远程看直播 | 半托管 / 不托管提供**真实下地**的入口，亲子、研学、周末农夫场景天然成立 |
| 复购只发生在"续费"这一刻，一年一次 | 农资是**高频消耗品**（种子、肥料、农具、代管），把年频消费变成季频/月频 |
| 农场人工成本刚性，认养费降不下来 | 把日常人工"还给"用户，农场只保留高价值环节（统防统治、整地、采收），成本结构随之下降 |

**收入结构对比（66㎡ / 12 个月，示例测算）**

| 项目 | 全托管 | 半托管 | 不托管 |
|---|---|---|---|
| 认养费 | ¥1,280 | ¥860 | ¥500 |
| 农资自购（种子/肥/工具） | 含 | ≈ ¥380 | ≈ ¥470 |
| 代管服务（浇水/代耕/代发） | 含 | ≈ ¥240 | ≈ ¥360 |
| **农场全年 ARPU** | **¥1,280** | **≈ ¥1,480** | **≈ ¥1,330** |
| 农场人工投入 | 100% | ≈ 55% | ≈ 20% |
| 毛利（示意） | ≈ 32% | ≈ 44% | ≈ 51% |

> 结论：**降低门槛 ≠ 降低收入**。半托管 ARPU 反而高出约 16%，因为用户为自己的参与付费；农场人工下降，毛利上升。

## 二、三档模式定义（系统与合同的共同基准）

| 维度 | 全托管 | 半托管 | 不托管 |
|---|---|---|---|
| 口号 | 农场全包，您只管收货 | 关键农事管家做，日常您来 | 全程自己种，农场提供地和技术 |
| 认养费 | 基准价 | 基准 − ¥420 | 基准 − ¥780 |
| 农场负责 | 全部农事 + 投入品 + 保险 | 整地/播种/统防/采收 + 12 次配送 | 土地/水电/工具借用/技术指导/监控 |
| 用户负责 | 无 | 浇水、除草、搭架、追肥（农资自购） | 全部农事（农资自购） |
| 每周待办（C 端） | 0 项 | ≈ 2 项 | ≈ 5 项 |
| 产出承诺 | **保底 240 斤，不足补足** | 按实际交付，不保底 | 风险自担 |
| 农业保险 | 含 | 统防部分含 | 建议自购（¥96/年） |
| 合同模板 | 标准合同 v3.2 | 半托管 v2.1（含责任划分附件） | 不托管 v1.4（土地租赁 + 服务协议） |
| 适合人群 | 异地、没时间、要稳定产出 | 周末能来、想参与、亲子体验 | 有经验、追求完整体验、价格敏感 |

**切换规则**：每周期可切换 1 次。低→高补差价；高→低按剩余周期折算退差额（扣已发生投入）。地块编号、摄像头绑定、历史档案连续保留。

## 三、系统改造：数据模型（ER 增补）

### 1. 认养商品维度
```
adoption_sku（认养商品）
  + care_modes        JSON   ['full','semi','self']   该商品开放哪几档
  + default_care      ENUM   默认选中档位

care_mode_config（托管模式配置，sku × mode 一行）
  + sku_id / mode
  + price_delta       INT    相对基准价的差价（负值为减）
  + duty_matrix       JSON   13 个农事环节 → 执行方（farm / customer）
  + output_promise    VARCHAR 产出承诺文案（受合规校验）
  + contract_tpl_id           绑定的合同模板版本
  + switch_rule       JSON   切换与补差价规则
  + supply_package    JSON   默认推荐农资包 SKU 列表
```

### 2. 农资商城
```
supply_spu（农资/服务商品）
  + cat            ENUM  seed|fert|tool|bio|svc|ins
  + fit_modes      JSON  ['semi','self']  适用托管模式
  + retail_allowed BOOL  **可售性开关**（化学农药强制 false）
  + need_workorder BOOL  购买后是否自动生成服务工单（生物防治 = true）
  + batch_no             批次号（写入溯源的关键字段）
  + bind_land_type       适用地块类型/面积

supply_order（农资订单）
  + adoption_id / land_id   **必须绑定地块**
  + deliver_way   ENUM  寄存基地 | 快递到家 | 基地自提 | 农场代施 | 电子保单
  + trace_state   ENUM  待登记 | 已写入     ← 未写入则地块档案标"待补充"
```

### 3. 投入品台账（跨来源合并）
```
input_record（投入品记录）
  + source   ENUM  farm（农场投入）| customer（认养人自购）
  + batch_no / used_at / dosage / operator
  → 两个来源在 C 端「溯源档案 - 投入品清单」合并展示，第三方检测时统一出具
```

### 4. 任务引擎与工单
```
task_template（任务模板）
  + trigger     ENUM  crop_calendar（作物日历）| iot_threshold（IoT 阈值）| manual
  + trigger_rule      例：soil_moisture < 22% AND rain_48h = 0 → 浇水
  + owner       ENUM  keeper | customer      ← 由 duty_matrix 自动决定
  + overdue_action    JSON  逾期 N 小时 → 推送"委托代办"营销位

service_order（代管服务工单）
  + from_task_id / land_id / customer_id / keeper_id
  + price / split_rule（管家 70% / 农场 20% / 平台 10%）
  + proof_photos / gps / 完成时间  → 自动写入生长档案
```

## 四、任务引擎：三档模式下的分流

```
作物日历 + IoT 数据  ──►  生成农事任务
                            │
              duty_matrix 判定执行方
              ├── farm     → 管家 App 任务池（打卡 → 生长档案）
              └── customer → C 端「自管任务」列表（推送提醒）
                                │
                          逾期 48h 未处理
                                ▼
                   自动推送「委托管家代办」→ 生成 service_order → 分账
```

**这是整个设计里最值钱的一条自动化**：自管任务逾期不是"服务失败"，而是**商机**。某试点基地上月由此转化 68 单、¥6,240 纯增量收入。

## 五、合规要点（系统强制，不是可选项）

| 风险点 | 系统处理 |
|---|---|
| 农药零售给个人（违禁且高危） | 类目级开关：化学农药 `retail_allowed = false`，只能作为"农场代施服务"绑定工单出售 |
| 认养人自带来源不明投入品，污染基地合规 | 自购农资**必须登记批次 + 施用时间**；未登记则该地块档案标"待补充"，第三方检测报告无法出具 |
| 半托管/不托管下产出责任纠纷 | 合同分版本（v3.2 / v2.1 / v1.4），责任边界条款随模式自动生成；页面禁止出现"保底""稳赚"等词，系统自动改写 |
| 用户把"自己种"理解为"稳赚" | 下单页按模式展示不同的《产出浮动告知书》与《免责条款》，勾选后方可支付 |
| 农资销售的资质问题 | 种子 / 肥料 / 农具可零售；农药类只走服务工单；保险类走合作机构出单，平台不触碰资金 |
| 资金与分账 | 认养费与农资款均进经营者对公账户、第三方监管；代管工单走微信支付分账（T+1，未完成冻结） |

## 六、三端原型改造清单（已完成）

**消费者小程序（07）** — 41 → **47 页**
- 商品详情：新增「选择托管方式」三档卡片（价格联动、服务边界、产出与责任），半托管/不托管追加「需自备农资」推荐位
- 规格选择弹层：新增「托管方式」维度
- 确认订单：显示托管方式；半托管以上追加「农资待备」提示卡
- 新增 6 页：**托管方式对比**（13 项服务 × 三档责任矩阵）、**农资与服务商城**（6 分类 + 地块绑定 + 批次溯源）、**农资详情**、**农资结算**、**我的农资**（含投入品溯源说明）、**自管任务**（待办 / 已完成，含委托代办、加购、到访三种处理）
- 认养详情：顶部托管徽标、托管方式缩略卡（含本周待办）、服务宫格扩至 12 项（新增农资商城 / 自管任务 / 我的农资 / 代管服务）
- 溯源档案：投入品清单区分「农场投入 / 认养人自购」两个来源
- 我的认养、我的、首页金刚区：新增入口

**经营者后台（08）** — 30 → **34 页**
- **托管模式配置**：三档定价、农事责任矩阵（决定任务派给谁）、默认农资包、任务触发规则、合规强制项
- **农资与服务商品**：11 个 SKU、成本/毛利/库存/批次/适用模式、可售性校验、代管收入 KPI
- **农资订单**：绑定地块、交付方式、**投入品留痕**字段（强制）
- **代管服务工单**：工单列表、分账规则（70/20/10）、执行留痕链路、逾期转化数据

**管家 App（09）** — 14 → **17 页**
- **农资代办**：代收 / 寄存 / 代施 / 安装，批次登记后方可闭环
- **代管服务工单**：接单 → 执行打卡 → 拍照回传 → 分账到账
- **自管认养人指导**：自管地块待办提醒、逾期转化委托、指导沟通（明确"不代替执行"）
- 任务清单：顶部说明任务已按托管模式分流，并给出自管认养人待办入口

## 七、落地建议（MVP 顺序）

1. **P0（必做）**：商品维度 `care_modes` + 合同分版本 + 责任矩阵 → 先把三档卖起来，农资可以先用"线下登记"兜底
2. **P1**：农资商城（SPU + 批次 + 绑定地块）+ 投入品台账合并 → 打通"透明"叙事
3. **P2**：任务引擎（作物日历 + IoT 阈值）+ 自管任务推送 → 提升自管用户的完成率与到访率
4. **P3**：代管工单 + 分账 + 逾期转化 → 纯增量收入，也是半托管模式的留存关键

## 八、销售话术要点（给经营者讲）

> 「同样一块地，你现在只能卖一种价。加了托管模式，你可以卖三种价：**想省心的卖 1280，想参与的卖 860，想自己种的卖 500**。门槛降下来，进来的人多了；进来的人会买种子、买肥料、买浇水代管 —— 全年算下来，半托管客户比你现在的全托管客户还多花 200 块，而你的活儿少干一半。合同、责任、投入品留痕，系统全帮你自动生成，你不用自己想怎么免责。」
