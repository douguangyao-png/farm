## 1. 调研

- **目标：** ① 后台 demo 与原型 08 一致；② 补原型里有而 demo 没有的页面；③ 在芋道 Java 里实现 farm 模块接口，前端从 mock 切到真后端。
- **现状 [实测]：** 原型 08 约 34 页；现有后台 `web-admin/src/views/farm/` 有 15 个目录。mock-server 已实现全部 farm 接口，契约在 `docs/api/farm-接口契约.md`。
- **缺口（初判，需逐页对照后定稿）：** 合同管理、退款审核、IoT 设备、视频监控、客户管理、管家管理、交易流水、分账结算、经营分析、资质证照、资金公示、托管模式配置（现在可能在商品表单里）、消息模板。
- **本轮不做（用户选择）：** 优惠券、活动管理、推广合规设置里的营销项、内容运营（社区）、客户分层与社群运营。这与 demo 方案的「不做」一致，无需改。
- **本机环境 [实测]：** JDK 21、Maven 3.9.12 可用；本机内存紧，测试和构建按已有约定去服务器跑。
- **未查清（先标出来）：** ① 本机没有找到 `ruoyi-vue-pro` 源码目录，需确认用 master-jdk17 分支还是别的；② 服务器上有没有 MySQL / Redis、JDK 版本、端口占用；③ 真后端需不需要和 mock 同时保留（建议保留，用构建变量切换，已有 R-7）。

## 2. 需求（待逐条细化）

- R-1 对齐：逐页对照原型，字段、列、筛选、文案、配色与原型一致；差异清单作为附件，逐条打勾。验收：差异清单全部关闭，每页有原型/实现并排截图。
- R-2 补页：缺口页面按原型实现，mock-server 同步补接口并更新契约。验收：新页面登录后可打开，数据来自接口。
- R-3 真后端：farm 模块接口在芋道里实现，路径、字段与契约一致。验收：用同一套接口测试分别打 mock 和真后端，结果一致。
- R-4 租户隔离、违禁词、未签合同不能支付、逾期委托等 mock 里已有的规则，真后端行为一致。
- R-5 部署：先备份，写回滚命令；部署后走登录后的页面，不只测 401。

不做：营销、社区、客户分层；真实支付、分账、电子合同、IoT 接入（仍为演示数据）；繁育。
