## 0. 怎么读这份清单

- 方法：直接读 HTML 源码里 `PAGES.xxx` 的渲染函数，提取表头、筛选项、按钮、统计卡片、状态标签，再对照 `web-admin/src/views/farm/**`、`app-member/pages/farm/**`、`app-steward/src/pages-farm/**` 的模板。没有打开浏览器看渲染效果。
- 出处写法：`08 L479 goodsList` = docs/08 的第 479 行起的 `PAGES.goodsList`；`07`、`09` 同理。行号是函数起点，细节在其后 20～60 行内。
- 标注：[实测] = 读源码看到的；[推测] = 由代码推断；第 7 节单列没确认的事。
- 结论四类：一致 / 有差异 / 缺失 / 方案已排除（demo 方案「不做」里的：繁育、营销券拼团分销、社区、会员积分、AI 问诊、真实支付/分账/电子合同/IoT 接入/直播）。
- 原型 08 实际有 34 个页面（`PAGES` 对象），C 端 07 有 47 个，管家端 09 有 17 个。docs/06 是 07 的早期版本（只有 7 个 screen：首页、商品、订单、我的、认养、社区），没有逐页对。

## 4. 缺失功能清单与分期
